# 设置内 System Prompt 会话级生效 — 设计文档

## 概述

将「设置」中的系统提示词编辑从**全局默认**改为**仅当前选中会话**：新建会话始终用全局默认初始化并写入该会话；用户在设置中的修改只持久化到当前会话；切换会话时展示并使用对应会话已保存的文案。

## 需求（验收口径）

1. **新建会话**：每次新建会话时，其 system prompt 初始值为当时的 `AppSettings.defaultSystemPrompt`（全局默认），并**立即写入该会话的存储**（`Conversation.systemPrompt` 字段存一份明确字符串），与后续是否再改全局默认无关。
2. **设置中修改**：用户在设置里编辑系统提示词并保存后，仅更新**当前选中会话**的 `systemPrompt`；不改写 `settings.json` 中的 `defaultSystemPrompt`，其它会话不受影响。
3. **切换会话**：选中某条会话时，设置中的系统提示词展示为该会话已保存的 `systemPrompt`；发消息时使用的 system prompt 与该会话存储一致。

## 数据模型（不变更字段含义）

- **`AppSettings.defaultSystemPrompt`**：仍为全局默认，**仅用于**新建会话时的初始拷贝；本功能不在设置页的「当前会话系统提示词」编辑框中修改该字段。
- **`Conversation.systemPrompt`**：每条会话独有；新建时已显式写入默认副本；用户在设置中的修改只更新当前会话此字段。

发送请求时的解析规则保持：**以会话字段为准**（新建已写入默认后通常总有字符串）；若历史数据中存在缺失字段的旧会话，仍可采用 `conversation.systemPrompt || settings.defaultSystemPrompt` 作为兜底，与本设计不冲突。

## UI / 交互

- **设置对话框**中原「默认系统提示词」改为「当前会话系统提示词」（或等价文案），辅助说明：**仅作用于当前选中的会话**；新建会话仍使用应用保存的全局默认作为初始内容（不在此处编辑全局默认）。
- **无选中会话**（例如列表为空或未选中）：该区块禁用或隐藏，并提示用户先选择或创建会话。
- **保存**：保存设置时，API Key、Base URL、存储路径等仍走现有 `saveServerSettings`；若存在当前会话且提示词区块可用，则额外调用会话更新接口，将文本框内容写入当前会话的 `systemPrompt`。
- **文本框内容**：绑定当前 `activeConversation.systemPrompt`（新建会话已写入默认，一般总有值）。无需「占位继承」交互；旧数据若为空则仍可显示兜底全局默认并允许保存以固化。

## 新建与会话创建路径（须一致）

以下路径在创建 `Conversation` 时均应执行 **`systemPrompt: settings.defaultSystemPrompt`（或当时的全局默认快照）**：

- 用户通过「新建对话」流程创建（含 System Prompt 模态中选「使用默认」或等价分支）。
- 当前无任何会话时用户首次发消息触发的隐式创建。

若新建流程中存在「自定义 system prompt」分支，则仍以用户确认为准写入该会话，不要求等于全局默认。

## 错误处理与竞态（原则）

- 设置保存若拆分多次请求：会话更新失败时应向用户提示，并避免误以为已成功；不要求自动回滚已成功写入的其它设置项（与现有简单错误处理对齐即可）。
- 若在保存过程中用户切换了会话：以实现简单为准——可在保存时使用保存开始时的会话 id 校验，不匹配则提示重新打开设置后再保存。

## 向后兼容

- 已有对话 JSON 若无 `systemPrompt` 字段：发送与展示继续依赖全局默认兜底；用户可在设置中打开该会话后保存一次以写入明确副本。
- 不在此次引入新的持久化文件格式版本号。

## 测试建议（手工）

- 新建会话 A、B，确认磁盘上两条会话的 `systemPrompt` 均为当前全局默认文本。
- 在会话 A 的设置中修改 prompt 并保存，切换到 B，确认 B 仍为初始文案；再切回 A，确认仍为修改后文案。
- 修改全局 `defaultSystemPrompt`（仅测试可通过直接编辑 `settings.json`）：新建会话 C 使用新默认；A/B 保持各自已存文案不变。

## 非范围（明确不做）

- **不提供**在同一设置文本框内编辑「今后所有新建会话的全局默认」（若产品后续需要，应单独增加控件或入口，避免与会话级编辑混淆）。
- 不提供「清空 system prompt 且绝不发送 system 消息」等特殊语义；空字符串行为维持现有代码约定（若 `||` 兜底则仍使用全局默认）。
